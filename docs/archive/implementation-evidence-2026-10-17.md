### 3.7 完整 Agent 链优先（2026-10-14）

- **范围调整：** 优先跑通 Main 委派、工具执行、独立审校、候选回传、正常确认、核验落盘和资源清理；不推进 UI 装饰、更多 SDK、更多代理层级或第二套执行机制。沿用现有生产 factory／service／pump／Supervisor 和前台队列。
- **模型交付契约：** 原本要求模型输出完整 durable delivery，却未提供隐藏运行身份和完整字段说明。改为业务结果 DTO，复用域字段类型并提供有界模板、数组项结构和枚举；schema／路由身份／delivery ID／revision 由宿主补齐，拒绝模型伪造。持久格式不变，不保留第二套旧解析。Worker 和 Reviewer 都拒绝非 EndTurn 终态；Reviewer 得到完整结果契约及未丢失的 verification status。
- **生产装配缺口：** 类型擦除服务漏转发 `materialize_change_for_session`，真实 Main 工具一直返回默认未就绪；已补齐。新的真 Git＋SQLite 组合回归通过正常 `delegate_work`、Supervisor outbox 和生产 factory 运行写候选／回读／模型业务 JSON／独立 Reviewer／Main 工具，不再只直测底层。
- **执行与交付生命周期分离：** 候选准备冻结工作包后，调度器曾将仍标记 running 的生产者封存为 policy-ineligible，导致待确认结果不可用。终态事件现在先撤销生产者 lease 并封存 sandbox，保留 delegation 的 awaiting_summary 和不可变候选；主 Agent 的接受与清理仍是另一阶段。恢复复用同一封存机制，不重跑生产者。
- **回到原主对话：** 复用既有 source-bound follow-up queue 补齐 ready Change 候选及审校 failed／needs_decision 的已交付结果。只有 passed Explorer 有精确 ID 的结果确认工具；候选、审校未通过、来源缺失或未知时摘要工具面均为空，不自动重试、接受或丢弃结果。候选说明范围、证据和风险，明确尚未写入，等待交互确认；审校问题说明缺失证据和待决定事项。成功只结算通知；模型服务失败或空摘要仍待跟进。启动恢复补齐审校／候选准备至队列之间的缺口，去重不创建第二次摘要。
- **确认重入：** 完整 applied receipt 和绑定均匹配时，只补主 Agent 接受／清理，不重新打开已回收 worktree 或重复写入。未知／不完整副作用不允许自动重放；清理待恢复不改写已经持久接受的成功事实。未取得 applied receipt 的中断仍需人工核对，不声称所有崩溃窗口都能自动恢复。
- **摘要上下文范围：** 自动跟进的 delivery ID 来自可信队列绑定，不解析用户或模型文本；在普通上下文数量上限之前精确筛选该结果，避免积压时漏掉目标或混入其他委派。目标已失效时停止本次摘要，沿原队列状态核对，不生成无依据的完成说明；不扩大既有上下文预算。
- **清理隐藏的额外模型调用：** 桌面日志发现每次用户输入仍会后台调用硬编码 DeepSeek 生成标题，即使当前主模型并非 DeepSeek、工作区标题已经存在。移除该旧函数与后台任务，沿用 Workspace 创建时的稳定主对话标题，避免无关供应商接收消息和额外请求；没有新建标题服务或另一套模型路由。
- **测试凭据隔离：** 发现启动器过滤环境后，应用和 debug HTTP 线程仍会重新加载仓库 `.env`。已合并为一个启动环境入口，单元测试／desktop-e2e 构建在编译期排除读取，普通应用行为不变；扩展既有桌面构建隔离测试，不读取或展示 `.env` 内容，不更改用户密钥。
- **核心回归证据：** worker 格式与身份、Reviewer 完整终态、生产装配、候选通知／服务失败恢复、隔离至确认、真实 Git 内容写入、重复确认和 sandbox／worktree 清理均有确定性回归；契约、回传和重复确认问题先红后修。审校未通过、空摘要、缺失来源和上下文数量上限亦已回归。使用生产装配并替换模型响应，不代表真实 Luna 对任务的理解或审校质量已验收。
- **最终验证：** 当前源码 canonical `full` 9/9（64 个前端文件／650 项测试；1156 Rust 通过、0 失败、3 项原生入口按设计忽略），前端测试 31.5 秒，Rust 测试检查 204.8 秒。既有桌面构建隔离的 2 项 Python 测试通过，覆盖测试不加载 `.env` 和旧标题请求移除。普通桌面构建 51.0 秒、隔离 feature 构建 56.9 秒均成功；后者只验证编译，没有将尚未通过的截图旅程改记成功。构建中的既有未使用项警告仍在；普通应用未启动，未运行用户真实日程，未提交或推送。

- **实现范围：** 复用 Supervisor 的活动投影、宿主事件、当前主对话任务卡和 ForegroundContextAssembler。不伪造交付、Reviewer 结论、助手消息或模型任务；无需新数据库表、IPC、轮询器、调度器或第三方依赖。安全原因分别说明任务模型、隔离目录、授权／配置、能力、执行环境、提交前退出和租约到期；未知启动分类采用固定泛化文案。旧版失败／策略共用事件无法证明具体原因，采用 `unclassified_stop` 和原因待核对说明，不错误诊断为策略变更。原始异常／路径／密钥不进入投影或提示词。
- **运行联动：** 实际 worker 无交付退出改记 `worker_failed`，不再冒充 `attempt_policy_ineligible`；既有撤权、停止和 sandbox／worktree 清理保持不变。心跳、交付、审校及失败都绑定当前最新 Attempt，终止任务不保留活动阶段，重试不继承旧结论或旧审校，游标至少覆盖该任务终态更新时间。主对话已有“需要处理”区展示原因及下一步，工作台避免重复显示同一原因。

- Main Agent 可结构化查询当前 Workspace 的自动化及执行回执，并按确切 ID 暂停后续定时；暂停服从统一操作权限，不停止已启动的程序、不删除历史。一次性提醒查询／取消仍保持原范围。空状态和已有内容的主对话共用折叠的事项回看，展示待执行、今日触发和运行结果；未知空间不退回全局列表，切换空间不显示旧结果。工具回合收尾、自动化更新与重新聚焦沿用同一刷新契约，不增加轮询或第二套调度器。
- 文件能力按 Workspace 装配：个人空间不注册任何项目文件工具；项目空间可结构化列出目录，并在不覆盖目标、不越过项目根目录的前提下复制文件或移动/重命名文件与目录。所有修改继续使用统一确认接口。
- Windows 桌面能力采用“先发现、后行动”的受控目录：Main Agent 可读取当前仍可用的受信任应用 ID、预定义系统设置页与当前 Workspace 文件能力；失效或停用应用不会进入行动工具枚举。个人空间不获得文件管理器定位能力；草稿和单字段填写都不点击提交/发送，程序路径、UIA 真实身份与任意外部路径不暴露给模型。设置页可对已保存的受信任应用只读查找草稿输入框名称，选择后仍须保存；通用字段填写另需默认关闭的授权，并从完整观察结果取得短时引用。运行时只接受唯一的该程序主窗口与预检目标；结果未知时暂停 Main Agent，不自动重试。“打开请求已发出”和“字段已校验”在 UI 中分开展示。
- Agent 自动化会以归属 Workspace 的 Main Agent 输入持久化入队，并由应用自有的合并调度器投递到该 Workspace 唯一主对话；它不生成伪造用户消息，也不会另起第二套 Agent。每次投递先持久化稳定的前台回复身份：尚未越过前台运行预留边界的任务可安全重试；已越过边界而中断的任务只会在原会话中显式标为可继续，绝不自动重放可能有副作用的操作。数据库关闭并重开后，未启动项恢复排队、已启动项恢复其可见终态，不会静默丢失或跨项目投递。
- MCP 服务属于已安装能力，不会自动进入任何 Main Agent 工具面；用户须在设置中为具体 Workspace 显式启用，未启用的服务器不会被注册为该会话工具。MCP 的确认与全局执行权限一致：请求批准时逐次确认，工作区自动与完全访问时可自动执行已获该 Workspace 准入的服务；执行权限不会新增服务或 Workspace 访问范围。多个服务的同名工具以可读服务名、工具名和稳定身份后缀注册，不会静默覆盖。待确认的 MCP 调用会持久化当时的输入 schema 修订，并在真正 `tools/call` 前强制重新发现工具；schema 漂移、工具消失、Workspace 撤销或历史记录缺少快照都会拒绝执行。任务级租约仍是后续工作。
- 原生 Web Search 是独立的受控外部查询能力：仅在设置中启用且已配置受信任 endpoint 时装配；默认执行权限下，每次发送查询前都显示不含密钥的确认。聊天中的搜索配置以独立、脱敏载荷交付后端，不写入普通消息或模型上下文；调用只返回有上限的结构化、不可信证据。关闭能力或移除 endpoint 后，后续回合和调用都不会取得该工具。
- 委派网络探索已有最小前台闭环：`delegate_network_exploration` 无论广泛执行权限如何都走一次精确用户确认；待确认步骤持久化后，只能用同一 `sessionId`、`messageId`、`callId` 恢复受限工具面。确认创建可撤销的项目范围来源批准，同项目中仅可复用给 host/action 均为其子集的请求；每个 worker attempt 仍须单独签发 lease。用户确认 UI 只显示规范化 host、动作和固定上限，绝不显示原始查询、完整 URL 或路径、凭据、密钥及其他秘密。
- 委派网络探索的核心运行时边界已闭合：批准撤销/策略摘要在每次 gateway 调用及 transport 返回后复核，项目批准复用时每个 lease 都收窄到 `ExplorerPlan` host 子集，search/fetch 均按批准策略而非全局上限限制 MIME 与响应字节，并在 evidence 投影前重载运行态 lease。项目设置已能以脱敏投影查看并幂等撤销当前项目批准；Explorer task 的同一取消信号贯穿 gateway、HTTP 请求等待与响应体读取，取消后停止重定向和证据投影。已发送请求不能远端撤回、同步 DNS 不可中止，真实桌面长旅程验收仍待完成。

### 尚未达到日常可用标准的缺口

1. **可靠性基线已恢复，但必须持续守住。** 委派运行时会封存重启时已领取但副作用未知的任务，Agent 自动化的已入队输入也已覆盖跨数据库重开恢复。以本文最近的阶段验收记录为准，不把历史测试数量作为当前结论；每次交付仍须通过离线 `full`。全量绿色不代表系统通知实际送达、真实模型理解正确或任意应用业务任务已完成。
2. **委派场景验收不完整。** 任意终态取消与“通过独立审校的候选被拒绝”均已通过真实 Git worktree、持久化资源绑定和生产清理适配器的组合回归；后者还验证候选不会写入规范项目，并会持久化为 `declined`、关闭 Change handoff。两条路径都验证 attempt 封存、能力租约撤销、Workspace admission 释放、sandbox 隔离及临时 worktree 删除。仍需覆盖并发上限、重启恢复、取消/转向、超时、失败重试与确认失效的端到端状态机。
3. **真实日常事务的权限体验未闭环。** 自动化、MCP、网络探索与文件修改必须统一经过可解释的能力/确认流程，并有可恢复的失败呈现。
   主对话现已支持当前空间的自动化查询、暂停和结果回看，不需要先切换自动化页。仍需验证真实第三方服务与模型下的多步业务结果；触发、脚本退出和 MAA 队列结束均不能替代业务目标完成或系统通知送达证明。
   普通确认后的执行已转由后端持有，不依赖当前工作区页面；历史续跑在预留事务中核对来源与活动末尾，自动化回执跟随新切片并同步终态。停止、拒绝和未知结果不会自动重放；没有通过无条件消费 `resumable` 改变分支回溯语义。验收与仍需验证的真实业务边界见下方“自动化确认续跑与回执闭环”。
4. **发布质量门仍未闭环。** GitHub Actions 已在 Windows 上执行 `python scripts/verify.py full` 与隔离运行时的桌面首次启动烟测；离线数据库的关闭/重开迁移回归已覆盖。仍需按 [`desktop-beta-checklist.md`](../desktop-beta-checklist.md) 执行并记录人工可用性验收，并逐步扩展已验证的桌面关键旅程。
5. **委派网络的产品闭环仍未完成。** fail-closed 运行时链路、项目设置中的批准查看/撤销，以及本地在途 HTTP 取消已有确定性回归；已发送请求不能远端撤回，系统 DNS 仍不可中止。需要以真实桌面关键旅程验收确认确认、查看、撤销、取消和失败恢复的组合，才可把它描述为成熟的日常能力。
6. **通用 computer use 尚未就绪。** Windows 原生能力已有应用启动、预设系统设置、项目文件定位、草稿/单字段填写、有界 UIA 观察和受控控件操作。`operate_trusted_app_control` 统一承接 Invoke、Select、Expand/Collapse，以及有名称且支持 ScrollPattern 的容器小步上下滚动；不新增工具或权限。现场预检绑定应用、窗口、控件和具体动作，每次操作仍需精确确认。Invoke 只证明派发，其他 `verified` 仅证明控件状态或滚动方向/已触边，不表示业务完成；已到目标状态或滚动边界不重复操作。所有 UIA 路径共用非阻塞并发门，跨工作区重叠请求返回 `TARGET_BUSY`，不排队或自动重试。操作后该应用旧引用全部失效；配置撤销再恢复或删除重建使旧预览失效，未知结果停止续跑。旧 Invoke 生产入口已替换，旧历史可显示但旧待审批不可执行。组合框/列表项名称隐私限制、完整快照和输出预算仍保留；浏览器内容语义、视觉操作和跨应用事务验证仍缺失，不以键鼠/坐标点击静默兜底。

### 2026-10-08 现有辅助软件的日常托管（首个场景：MAA）

- 下一条优先验收旅程是：用户向 Main Agent 提供已有辅助软件和日常要求，助手检查已有配置、提出一次可理解的计划，再按批准的范围配置每日执行。MAA／MuMu 是首个样本，不把 AngelBot 改成游戏执行引擎。
- **最新约束：辅助软件按需启动，不开机自启或等待定时而常驻。** 每日北京时间 18:00、沿用当前任务已确认；AngelBot 复用自身既有自动化持久化与调度作为唯一触发方，目标流程为到点启动 → 显式开始当前任务 → 跟踪结果 → 正常关闭本次启动的实例。已有用户实例不由该流程关闭，不以每日调用模型或按软件名强杀进程代替控制。MAA v6.18.0 的重复启动只唤起既有窗口，不能作为开始任务的接口。

### 2026-10-09 脚本自动化的执行与恢复基础

- 手动运行和到期脚本复用同一事务准入：外部执行前先保存 `running` 回执，结束时更新原回执，不另建终态记录。同一脚本定义的重复手动执行会拒绝；定时与正在运行的脚本重叠时记录跳过并推进计划，不在排队等待后补跑。到期扫描与实际开始执行分别检查重叠，避免前项耗时导致后项重复执行。
- 暂停只影响后续计划，不停止正在运行的进程，也不撤销其执行所有者；运行中不能删除定义。手动运行不移动未来的计划时间，结束回执使用实际结束时间；同秒产生的回执仍按创建先后稳定展示。
- 心跳恢复覆盖已暂停和非到期脚本；过期且不再由本进程持有的启动回执会转为 `attention_required`，暂停定时并保留证据，不自动重放。仍活跃的本地执行不会因时钟向前跳而被重新领取。用户须先核对上次执行已结束且不会重复产生副作用，再明确手动重试；获得明确结果后才能重新启用定时。这不是外部系统的 exactly-once 保证，也不是操作系统沙箱。
- 桌面 IPC 不在主线程同步等待脚本；自动化页与主对话事项回看共用刷新事件契约，只读刷新不调度或重试。页面拒绝迟到的加载结果覆盖新状态，展示持久启动回执而不把它称为进程仍存活；未知结果、失败／超时及跳过分别呈现。复用现有轮询兜底，不增加第二套调度器。

| `delegated-agent-framework-spec.md` | 委派的规范性契约与追踪矩阵 | 定义“应当如何” |
| `issues/` | 可独立完成的工作项 | 定义“这一项做什么” |
| `archive/historical/` 与 `research-*` | 历史原因与外部证据 | 不能作为当前状态或优先级来源 |

已解决的 issue 应移至 `issues/archive/completed/`；历史设计保留但必须标明历史属性。新文档不得再创建第二份“总路线图”。

## 6. 验收标准

每项实现至少满足：

1. 边界、状态和失败语义与本文及相关 ADR 一致；
2. 使用确定性测试，不依赖用户数据、网络或模型密钥；
3. focused change 跑 `python scripts/verify.py quick`，交付前跑 `python scripts/verify.py full`；
4. 涉及桌面交互时补充真实应用关键旅程验证；
5. 完成后更新本文的“当前事实”和相关 issue 状态，避免实现与计划再次漂移。
6. UI 改动不得只以静态截图验收：同时检查常态、悬停/聚焦、加载、成功、失败、禁用、空状态、深色和减少动态效果，并验证对应前后端行为仍可完成。
