# AngelBot 当前统一路线图

> **状态：当前唯一的实施路线图（更新至 2026-10-07）。**
>
> 本文统一产品目标、已确认架构决策、当前事实、未完成工作和验收顺序。实现、评审与后续规划必须以本文为入口；更细的规格、ADR、调研和 issue 只提供依据，不得覆盖本文的当前状态。

## 1. 产品目标与不可变边界

AngelBot 是本地优先、能长期陪伴并协助完成事务的桌面助手。用户始终只与一个 **Main Agent** 对话；它拥有完整上下文、决策权、确认权和用户可见的解释责任。

AngelBot 是通用个人助手，不以邮件、日历、编程或任一垂直场景定义自身。文件、应用、浏览器、自动化和 Connected Service 都通过同一套能力发现、授权、执行、验证与恢复机制接入；邮件和日历只是首批需要验证的连接能力。

2026-10-03 定位对齐：核心价值是减轻用户在应用、会话和执行工具之间切换、重复解释和跟进事务的负担。日常是主要入口，项目承载持续工作的资料和上下文，用户始终面对同一位 Main Agent；助手与结果为主，工作台按需展开。专业编码代理是可选执行能力，由 Main Agent 组织、跟进、审校和交付，不把自建重型编码 harness 或超大型项目自治作为核心目标。这个产品方向已确认，不代表外部引擎接入、日常文件能力或通用 computer use 已完成。

- **Workspace** 是稳定容器。个人空间不拥有项目文件，只保留项目索引；项目空间绑定一个项目根目录，并向用户投影一个主对话。
- **Session / Branch** 是内部恢复机制，不是用户操作子 Agent 的入口。
- 子 Agent 只能由 Main Agent 委派；不得递归委派、不得直接向用户对话、不得获得主工作区写权限。
- 真实项目写入只能来自经过审校且获确认的候选变更；候选工作在短生命周期 Git worktree / sandbox 中完成。
- 用户只看 Main Agent 级别的摘要、决策与结果；不暴露子 Agent 工具流水、百分比进度或控制入口。

术语以 [`../CONTEXT.md`](../CONTEXT.md) 为准；产品价值与用户主权边界以 [`design-philosophy.md`](design-philosophy.md) 为准。

## 3. 当前事实（而非目标）

### 已具备的基础

- 前台 Main Agent 的历史、压缩上下文、工具生命周期、持久化终态屏障和本地数据库迁移。
- 日常与项目对话可接收用户显式选中的有界 UTF-8 文本快照；附件独立于可见消息正文保存，历史、压缩、编辑重发与上下文计量使用同一数据契约。选文件不授予 Personal 文件夹访问能力，图片、PDF 和 Office 附件仍不支持读取。验收见下方 2026-10-04 记录。
- Workspace / Personal Workspace 数据模型与单一主对话投影的迁移基础。
- 委派的 WorkPackage、Attempt、Capability Lease、结构化 brief / delivery、临时 sandbox / worktree、候选变更与 review 基础模块。
- `delegate_work` 已经通过 Supervisor 工作队列：委派记录与 outbox 在事务中链接到 Supervisor work；只有 Dispatcher Adapter 授权后 runtime 才可领取。既有 pump 会恢复一项未授权的已持久化工作。
- 自动化、MCP、文件和分支等既有工作台能力仍保留，前端迁移不移除其入口。
- Main Agent 每轮遵循统一的 `reply / clarify / act` 决策契约：闲聊和讨论不因主题词误触发工具，只有缺少必要信息时才聚焦澄清，需要现实结果时才用原生工具调用表达行动。旧的关键词任务路由已移除，不再维护第二套意图分类器。
- 一次性本地提醒已经贯通 Main Agent 工具调用、现有确认策略、Workspace 归属、自动化持久化、到期认领、Windows 通知和完成态展示；重复自动化仍沿用原有 Agent / 脚本路径。
- Main Agent 可以结构化查询并取消当前 Workspace 的待提醒事项；取消沿用副作用确认且只停用记录，不删除历史证据。空状态和已有内容的主对话共用折叠的事项回看，按当前空间展示通知、Agent 和脚本的待执行及今日触发记录；未知空间不退回全局列表。回看范围不扩大一次性提醒工具的查询或取消范围。工具回合收尾、成功调度扫描与重新聚焦都会刷新，不伪造聊天消息，也不把触发记录称为任务完成或系统通知送达。
- 文件能力按 Workspace 装配：个人空间不注册任何项目文件工具；项目空间可结构化列出目录，并在不覆盖目标、不越过项目根目录的前提下复制文件或移动/重命名文件与目录。所有修改继续使用统一确认接口。
- Windows 桌面能力采用“先发现、后行动”的受控目录：Main Agent 可读取当前仍可用的受信任应用 ID、预定义系统设置页与当前 Workspace 文件能力；失效或停用应用不会进入行动工具枚举。个人空间不获得文件管理器定位能力；草稿和单字段填写都不点击提交/发送，程序路径、UIA 真实身份与任意外部路径不暴露给模型。设置页可对已保存的受信任应用只读查找草稿输入框名称，选择后仍须保存；通用字段填写另需默认关闭的授权，并从完整观察结果取得短时引用。运行时只接受唯一的该程序主窗口与预检目标；结果未知时暂停 Main Agent，不自动重试。“打开请求已发出”和“字段已校验”在 UI 中分开展示。
- Agent 自动化会以归属 Workspace 的 Main Agent 输入持久化入队，并由应用自有的合并调度器投递到该 Workspace 唯一主对话；它不生成伪造用户消息，也不会另起第二套 Agent。每次投递先持久化稳定的前台回复身份：尚未越过前台运行预留边界的任务可安全重试；已越过边界而中断的任务只会在原会话中显式标为可继续，绝不自动重放可能有副作用的操作。数据库关闭并重开后，未启动项恢复排队、已启动项恢复其可见终态，不会静默丢失或跨项目投递。
- MCP 服务属于已安装能力，不会自动进入任何 Main Agent 工具面；用户须在设置中为具体 Workspace 显式启用，未启用的服务器不会被注册为该会话工具。MCP 的确认与全局执行权限一致：请求批准时逐次确认，工作区自动与完全访问时可自动执行已获该 Workspace 准入的服务；执行权限不会新增服务或 Workspace 访问范围。多个服务的同名工具以可读服务名、工具名和稳定身份后缀注册，不会静默覆盖。待确认的 MCP 调用会持久化当时的输入 schema 修订，并在真正 `tools/call` 前强制重新发现工具；schema 漂移、工具消失、Workspace 撤销或历史记录缺少快照都会拒绝执行。任务级租约仍是后续工作。
- 原生 Web Search 是独立的受控外部查询能力：仅在设置中启用且已配置受信任 endpoint 时装配；默认执行权限下，每次发送查询前都显示不含密钥的确认。聊天中的搜索配置以独立、脱敏载荷交付后端，不写入普通消息或模型上下文；调用只返回有上限的结构化、不可信证据。关闭能力或移除 endpoint 后，后续回合和调用都不会取得该工具。
- 委派网络探索已有最小前台闭环：`delegate_network_exploration` 无论广泛执行权限如何都走一次精确用户确认；待确认步骤持久化后，只能用同一 `sessionId`、`messageId`、`callId` 恢复受限工具面。确认创建可撤销的项目范围来源批准，同项目中仅可复用给 host/action 均为其子集的请求；每个 worker attempt 仍须单独签发 lease。用户确认 UI 只显示规范化 host、动作和固定上限，绝不显示原始查询、完整 URL 或路径、凭据、密钥及其他秘密。
- 委派网络探索的核心运行时边界已闭合：批准撤销/策略摘要在每次 gateway 调用及 transport 返回后复核，项目批准复用时每个 lease 都收窄到 `ExplorerPlan` host 子集，search/fetch 均按批准策略而非全局上限限制 MIME 与响应字节，并在 evidence 投影前重载运行态 lease。项目设置已能以脱敏投影查看并幂等撤销当前项目批准；Explorer task 的同一取消信号贯穿 gateway、HTTP 请求等待与响应体读取，取消后停止重定向和证据投影。已发送请求不能远端撤回、同步 DNS 不可中止，真实桌面长旅程验收仍待完成。

### 尚未达到日常可用标准的缺口

1. **可靠性基线已恢复，但必须持续守住。** `global_two_attempt_limit_rejects_third_queue` 曾因测试夹具未为新增会话建立独立 Workspace 而失败，现已修复；委派运行时会封存重启时已领取但副作用未知的任务，Agent 自动化的已入队输入也已覆盖跨数据库重开恢复。全量验证当前通过（2026-10-04：前端 461 项通过、无跳过；Rust 963 个 library tests 通过，1 项原生交互桌面验收按设计忽略）。原生项此前已独立验收，本轮不冒充重新执行。原六条跳过测试已按当前主对话与监听设计恢复，不再保留旧审计布局断言。全量绿色仍不代表系统通知实际送达或任意应用业务任务已完成。
2. **委派场景验收不完整。** 任意终态取消与“通过独立审校的候选被拒绝”均已通过真实 Git worktree、持久化资源绑定和生产清理适配器的组合回归；后者还验证候选不会写入规范项目，并会持久化为 `declined`、关闭 Change handoff。两条路径都验证 attempt 封存、能力租约撤销、Workspace admission 释放、sandbox 隔离及临时 worktree 删除。仍需覆盖并发上限、重启恢复、取消/转向、超时、失败重试与确认失效的端到端状态机。
3. **真实日常事务的权限体验未闭环。** 自动化、MCP、网络探索与文件修改必须统一经过可解释的能力/确认流程，并有可恢复的失败呈现。
   已有内容的主对话现在可以回看当前空间的待执行事项和今日触发记录，不需要先切换自动化页。仍需验证真实第三方服务与模型下的多步业务结果；触发回执不能替代业务完成或系统通知送达证明。
4. **发布质量门仍未闭环。** GitHub Actions 已在 Windows 上执行 `python scripts/verify.py full` 与隔离运行时的桌面首次启动烟测；离线数据库的关闭/重开迁移回归已覆盖。仍需按 [`desktop-beta-checklist.md`](desktop-beta-checklist.md) 执行并记录人工可用性验收，并逐步扩展已验证的桌面关键旅程。
5. **委派网络的产品闭环仍未完成。** fail-closed 运行时链路、项目设置中的批准查看/撤销，以及本地在途 HTTP 取消已有确定性回归；已发送请求不能远端撤回，系统 DNS 仍不可中止。需要以真实桌面关键旅程验收确认确认、查看、撤销、取消和失败恢复的组合，才可把它描述为成熟的日常能力。
6. **通用 computer use 尚未就绪。** Windows 原生能力已有应用启动、预设系统设置、项目文件定位、草稿/单字段填写、有界 UIA 观察和受控控件操作。`operate_trusted_app_control` 统一承接 Invoke、Select、Expand/Collapse，以及有名称且支持 ScrollPattern 的容器小步上下滚动；不新增工具或权限。现场预检绑定应用、窗口、控件和具体动作，每次操作仍需精确确认。Invoke 只证明派发，其他 `verified` 仅证明控件状态或滚动方向/已触边，不表示业务完成；已到目标状态或滚动边界不重复操作。所有 UIA 路径共用非阻塞并发门，跨工作区重叠请求返回 `TARGET_BUSY`，不排队或自动重试。操作后该应用旧引用全部失效；配置撤销再恢复或删除重建使旧预览失效，未知结果停止续跑。旧 Invoke 生产入口已替换，旧历史可显示但旧待审批不可执行。组合框/列表项名称隐私限制、完整快照和输出预算仍保留；浏览器内容语义、视觉操作和跨应用事务验证仍缺失，不以键鼠/坐标点击静默兜底。

### 2026-10-07 Luna 日常能力与 Codex 专项适配

- 普通桌面版使用已连接的 `gpt-5.6-luna` / ChatGPT 套餐：本地提醒查询、一次性提醒持久化触发，以及只读 Agent 自动化投递到唯一主对话并调用工具、完成回执已有真实验收。曾出现创建后的模型连接失败及自动化的凭据读取／刷新失败；之后重测成功不证明偶发原因已修复。验收定义已暂停，失败历史保留。
- 自动化只暴露实际支持的每日频率；不支持的旧定义与排队项保守停用，已启动身份不重放。Agent 输入、运行回执与调度推进复用 Supervisor 单事务；暂停 Agent 的手动执行入口提示先启用，通知与脚本的行为不变。
- 已派发的 MCP 调用若无可靠结果，使用既有 `RESULT_UNKNOWN` 暂停，而不是普通参数错误重试。前台中断恢复按同任务／会话的持久化错误 code 投影固定安全失败提示，不输出底层诊断正文或改变完成／重放边界。
- 主对话回看改称“事项回看／待执行”，如实覆盖通知、Agent 与脚本；一次性提醒工具的查询／取消范围不扩大。
- 该日常验收阶段的 `python scripts/verify.py quick` 与 `full` 均通过：63 个前端文件、513 项前端测试，1060 项 Rust library tests，0 失败；1 项原有原生交互测试按设计忽略，未计入通过数。使用无真实模型凭据、离线依赖及临时数据的确定性配置，不替代上面的普通桌面实测。
- Codex 参考以公开工具契约、typed content、终态幂等和取消生命周期为主；不替换整个 harness，也不假定其完整桌面 helper 已开源。该阶段尚缺图像结果到模型的链路、浏览器正文语义与真实应用多步结果；图像基础链的后续实现见下一节。该日常验收没有获准应用可供实际操作，不把能力发现成功算作通用电脑操作完成。

详细事实与后续验收见 [Luna 日常能力验收](research/luna-daily-capability-validation-2026-10-07.md)，源码证据见 [Codex 日常能力适配参考](research/codex-daily-capability-reference-2026-10-07.md)。凭据故障安全分类及授权应用中的观察／动作／回读旅程仍需补齐，不新增并行权限或调度框架。

### 2026-10-07 工具图像传输基础链

- 已启用 MCP 工具返回的静态 PNG 可通过 `ToolResult`、Main Agent 当前回合和 Responses 的 `function_call_output` 图像数组进入模型，保留原 call ID、套餐连接和纯文本行为。复用已有 png 依赖，不新增视觉 Agent、工具调度器或前端 IPC。
- 图像有 MIME、解码、尺寸／像素／字节、数量及请求体预算；完整解码后再次拒绝尾部动画标记。旧 String 输出与 typed 内部输出共用同一 MCP 准入和发送路径，普通业务 structuredContent 保持兼容。
- 图像不进入序列化、私有会话、步骤或缓存；当前请求成功返回后释放。取消、失败／终止及调用后发现撤权时丢弃图像；撤权复用 `RESULT_UNKNOWN` 人工复核暂停，不自动重做。未接入图像的 provider 明确说明未发送，现有动态包装器转发能力标记。
- 最终 `python scripts/verify.py quick` 与 `full` 均通过：63 个前端文件、513 项前端测试，1083 项 Rust library tests，0 失败；1 项既有原生交互测试按设计忽略。新增 23 项有针对性的回归，复用既有 mock、参数化场景与本地 fixture，不读取真实凭据、用户数据库或外网服务。
- 普通 release 构建通过并已启动，只读核对主对话、Luna 模型标识与既有自动化状态；没有重新执行自动化、修改授权或发送新模型请求，不作为真实图像理解或安装包发布验收。
- 这不是 Windows 窗口截图、坐标执行、通用网页正文或真实 Luna 图像理解验收。下一步在现有 DesktopAdapter 与受信任应用范围内接入有界单窗口观察，再做真实“观察 → 预检／动作 → 回读 → 结果回流”旅程；不静默扩大权限。

实现边界、格式依据和验证记录见 [工具图像链路验收](research/tool-image-bridge-2026-10-07.md)。

### 2026-10-07 受信任单窗口观察

## 6. 验收标准

每项实现至少满足：

1. 边界、状态和失败语义与本文及相关 ADR 一致；
2. 使用确定性测试，不依赖用户数据、网络或模型密钥；
