> **当前实施路线图，整理于 2026-11-19。** 各项验收的日期和覆盖范围见正文。
>
> 本文只维护当前能力、有效验收、缺口与唯一推进顺序；不追加逐轮开发日记。固定历史见 [验收记录归档](archive/implementation-evidence-2026-10-17.md)。

## 1. 产品目标与不可变边界

AngelBot 是本地优先、面向单一用户的 Windows 通用个人助手；长期陪伴与减轻应用／任务切换负担是核心，不以邮件、编程、长程研究或大型项目自治定义自身。

用户只与 Main 对话，日常是入口，项目承载持续工作；每个项目一个可见主对话，文件／浏览器／任务工作台按需展开。Main 负责上下文组织、派发与交付，访问仍按空间隔离；子代理没有用户入口、递归委派或主项目写权限。候选 worktree／sandbox 是临时隔离资源，不是正式项目或 OS 沙箱。

日常／项目是互斥入口与上下文边界，不是能力等级：日常同样可用电脑、网页、文件和自动化。项目维持单一持续目标与独立主对话；回到日常只切换界面，不取消项目任务或改变授权。普通提及不等于项目执行请求。

完整产品和授权边界见 [设计原则](design-philosophy.md)，术语见 [CONTEXT.md](../CONTEXT.md)。习惯学习首先改善相处体验，不以强制流程优化替代业务能力。

## 3. 当前实现与验收总览

**当前优先级：发布暂停，优先验证并修复日常和项目任务所需的基础操作。** 首项是项目内的命令执行、失败回执和交付文件核对。长期记忆与其他附加能力在基础操作之后排期。

隔离后端已核实本地脚本的保存、手动／到点派发、真实落盘、重开查询和停止保护；模型任务本轮只核实排队／归属／取消，实际模型完成仍无单独证据。长资料的 8 KiB 整条过滤缺陷已修复，同一份 9,228 字节原文保持不变，自动与显式召回均从 0 条变为 1 条，返回带来源和“非全文”说明的相关片段；后续复核修正了早期通用词遮蔽尾部答案的问题。人物卡已修正中文 PNG、版本头与普通配置导入残留，支持 V1/V2/V3 文本人设与原卡字段保留，不宣称完整酒馆兼容。

**人物卡产品范围（11月4日，用户再次确认收敛）。** 世界书只作为可查看、选择和编辑的背景文字，保存为同一 profile 的 `personaNotes`，最多 4096 字；作为固定人设补充随对话提供，留空停用。已移除本轮尚未发布的世界书运行时关键词／条件筛选及相关 DTO，未采用自动摘要、RAG、新存储或酒馆剧情引擎。新卡导入先预览、默认不选条目，应用时清除上一张卡的人设补充；普通配置缺少卡字段时清除旧卡，缺少补充时清空补充。选定文字独立于个人记忆，不改变助手身份和执行权限；未选原文及卡内高优先级指令不进入该链路。前端导入／持久化及 Main 实际调用方定点通过，Rust DTO→配置→主助手上下文与无个人记忆写入通过；最终统一 `python scripts/verify.py full` **10/10、退出 0**：前端 844 项、Rust 1351 通过／20 ignored、离线协议 3 项通过；701 项受版本控制输入在验收前后逐字节一致。浏览器截图启动被自动审批拒绝（仅返回 blocked by policy），本轮视觉截图与真实模型行为仍未验证，未绕过限制。

CI 下载源修复已通过 PR #4 合并，主分支完整验证和桌面冒烟通过。原 UI、脚本与资料库实跑证据按原范围复用；此前 full 不替代本轮新增改动验收。下述早期预发布标准仍适用，但不能据此前发布安排自动恢复提交、推送或发布。

**多步文件任务与展示（11月5日）。** 当前源码隔离版以真实 `gpt-6-luna` 完成一轮订单核算。5 次模型请求，4 次成功读取、2 次批准后写入，最终读回两份交付文件，独立验算一致；输入原件保持完整，两个结果链接均能打开工作台。据此修复等待批准时把 78 个计划文字片段拆成段落的问题，任务页按同一对话的父消息链展示最近一次完成的文件步骤，报告预览复用 Markdown 渲染并提供源码切换。最终离线 `full` 10/10 通过，前端 845 项、Rust 1351 项和离线协议 3 项通过。修复后验证覆盖实测事件形态与回执链，真实模型执行证据沿用原任务。

**长期记忆核对与连接提示（11月5日）。** 助手提议保存长期记忆时展示正文、分类和适用范围，各权限模式均需单次确认。记忆管理可暂停和恢复召回，保留原文与操作历史。相关候选在本地按文字查找，限定为近期同范围、同分类的活跃记录，用户核对两条原文后可确认替代。召回内容以历史资料提供，当前更正优先。隔离实测中遇到的 ChatGPT 受保护授权读取失败现单独展示原因，可重新读取。

记忆管理可筛选「已替代」，核对原记录与替代记录的当前内容。撤销后，原记录回到「已暂停召回」，可另行恢复。批量遗忘跳过已替代记录，包括旧版保存的记录。

**项目命令的运行与回执。** 实际调用旧处理器时，短 Python 脚本正确写出结果，退出 7 的脚本返回错误，输出 256 KiB 的脚本却因等待退出后才读取管道而超时。本机 Windows 的 npm 通过 `npm.cmd` 安装，旧处理器直接查找 `npm` 也无法启动。项目命令现复用脚本自动化已有的有界输出读取与 Windows 进程树管理。输出超限时继续排空管道，回执保留截断提示和错误输出；非零退出、超时和取消仍以失败返回。Windows 包管理器可从 PATH 使用原生程序或批处理启动器，批处理参数复用现有字面值限制。回归用本地 Python 和 npm 临时脚本核对退出结果及落盘数据。

**基础任务的前台回归。** 整仓测试包含一条隔离项目任务，使用正式前台执行入口读入数据、写脚本、启动真实 Python 进程并读回报告。成功时独立核对磁盘内容。命令非零退出或正常退出但读不回报告时，任务应保留失败回执并标为待处理。三个用例都在数据库重开后复核回执，模型步骤由测试固定。

**真实模型的命令恢复（11月6日）。** 隔离前台以已连接的 `gpt-6-luna` 完成 7 次模型请求。模型从四种可用工具中选择列目录、读文件和执行命令，收到退出码 7 后根据错误补齐配置，重跑同一命令并读回报告。独立核对为 3 笔订单、调整后合计 62，输入和预置脚本保持原样。重开数据库后，两次命令的失败与成功回执都保留，任务状态为已完成。首轮夹具误拦合法的空根目录参数，在执行工具前停止，结果单独保留。此轮范围为无窗口隔离项目和自动执行模式。

**项目命令批准、停止与回执。** 命令确认卡显示程序、逐项参数和超时时间。自动执行在启动前记录派发，手动批准在启动前消费单次确认。如果执行结果来不及落库，工作区可能已经改变，界面提示先核对再发起新命令。以 SQLite 写入故障模拟回执丢失，确认真实命令只运行一次，重复批准和直接继续被拦截。无窗口隔离项目使用 `gpt-6-luna` 走正式批准和续跑链路，批准后一次执行，模型读回结果 42，重开后状态为已完成。首轮 TLS 连接失败发生在工具调用前。

运行中的停止回归通过正式会话停止入口中断已批准的 Python 命令，使用 Windows 进程句柄确认子进程退出，取消回执可查，后续写入没有发生，旧批准无法再次执行。

**任务终态评审回归。** 文件编辑和整理会作废之前的编码验证回执。实时执行与批准后的落库都使用同一规则。只有识别到的测试、构建或检查入口成功退出才计入编码验证，普通命令、帮助和测试列举仍保留各自的回执。已知失败后，同一命令仅调整超时再成功，可解除旧失败的阻挡。参数指向不同操作或结果未知时仍需核对。回归覆盖误判反例，也在正式前台用真实 Node 测试独立比较 Python 生成的报告与输入数据。

`agent_eval.py` 的合成任务评分现在逐项记录运行终态、实际结果、操作约束和最终答复，全部满足才通过。配送题要求报出确认后的星期，额外的只读核对不会导致扣分。新报告带 `stateRubricVersion: 2`，早期报告仍对应各自的题面与规则。前台离线回归还覆盖了退出码为 0 但报告数值错误的情况，独立验证器会拒绝该产物，并核对输入和验证脚本未被修改。评测设计参考 [τ²-bench 的结果评分](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md) 和 [SWE-bench 的修复与回归检查](https://www.swebench.com/SWE-bench/api/harness/)。

新规则下的 `gpt-6-luna` 隔离冒烟为 7/8。六道工具选择题通过，配送题完成读、改、复核和正确答复。记忆题把「饮茶」作为字面关键词，夹具返回空结果，模型答「无法确定」，因此未通过。两种检索提示试验都复现同一结果，提示改动已撤回。该记忆题使用合成检索工具。

评分版本 3 改用正式 `recall_memories` 和隔离 SQLite 记录，保留题面并独立核对检索输出和最终答复。定点测试确认只搜「饮茶」仍会查空，同一次调用补查「常喝」能返回正确记录。Luna 冒烟 8/8，记忆题通过「饮茶 常喝 茶」一次查询答出「白毫银针」。保留组记忆题答出「祁门红茶」，已替代和无关记录均未返回。保留组共 6/10，三道并行工具选择题失败，配送冲突题已改对并读回，但旧失败仍阻挡正常收尾并耗尽请求预算。

前台终态按执行回执判断。模型按用户要求和实际改动安排验证，运行器已移除根据措辞和文件名推断必跑测试的分支。用户要求跳过测试时，成功写入代码后可直接收尾。已执行的检查失败仍显示需关注，磁盘核对发现不一致时随原工具结果交给模型处理。

**冲突恢复与同批工具调用。** 工具明确回执版本冲突未产生副作用后，同工具仅更新声明的前置条件并成功执行，即可解除旧失败对收尾的阻挡。失败回执仍可查，改动目标变化或结果未知仍按失败处理。固定回放与 Luna 均以六次请求、一次实际写入并读回完成配送。工具提示补充同工具多组参数要分别调用，保留组由 6/10 到 8/10。剩余一题首批漏查宽度，另一题两条调用均发出，但表达式格式与参考答案不同，工具描述未约定该语法。报告逐项区分调用数量、工具参数校验和参考匹配。

`python scripts/agent_eval.py --suite workspace --live` 单独验收多份文件的实际交付，最多四次模型请求。使用正式 `read_file` 和隔离文件，不依赖 BFCL 数据。验收同时核对两份读取回执、输入完整性和最终分项／合计，首批调用数量单独记录。Luna 首批并发读取两份文件，第二次请求答出东区 247、西区 389、合计 636。此结果覆盖 AgentRunner 的真实文件读取，BFCL 仍独立衡量首批工具选择。

**日常混合交付（11月6日）。** `python scripts/agent_eval.py --suite daily --live` 在独立目录和合成记忆中，用正式读取、召回和写入工具完成一题。Luna 用 4/6 次请求读取东区 247、西区 389，写前召回现行标题「青灯月报」，仅写入一次 `invoice-summary.json` 并读回。独立读盘确认原件字节未变，产物和最终答复均符合分项、合计 636 和现行标题，检索未返回已替代或无关记录。确定性 Runner 回放和 Python 评分检查通过。长期记忆的重复保存、修订、遗忘和历史记录通过定向验收。侧栏在 1440px 和 800px 的隔离浏览器验证了按钮位置及焦点行为。整仓离线 10/10 通过。真实模型证据限受控任务，跨多日的自然记忆表现仍待观察。

**日常前端体验（11月6日）。** 隔离浏览器走通首次进入、模型设置入口、日常与项目往返、资料库分类及自动化列表。窄窗口关闭侧栏后不再聚焦到屏幕外，Escape 关闭侧栏并归还焦点，上层弹层优先关闭。切回项目时若后台任务恰在读取历史期间完成，主对话会补取已保存的最终回复。历史工具记录按最多四个并发读取，离开会话后停止排发。两个并发缺陷均有定点回归。整仓离线 10/10 通过，前端 856 项通过。后续仍需用原生窗口核对失败与未知结果的提示，以及跨工作区和重开时的状态同步。

**任务状态与交互（11月8日）。** 聊天按持久任务状态显示修复后的结果，仍可展开旧失败回执。模型初始化或执行失败先保存回复，再通知界面刷新。工作台区分执行中、委派状态未确认、操作结果待核对。隔离预览在 1440px 与 800px 核对了项目与日常往返。原生重开和通用待处理事项的结清仍待单独核对。

**人格提示词（11月8日）。** 空名称使用 AngelBot，简介和开场风格仍生效。已选世界书与历史核心记忆作为参考，当前明确设定优先，操作边界由宿主独立判定。首次发送、编辑重发和审批后的新一轮推理使用同一界面配置。手动继续接口可接收相同配置。已核对离线模型输入、长人设预算和 Anthropic 系统段组装。整仓离线 10/10 通过，前端 861 项、Rust 1372 项、开发桌面协议 3 项通过。真实模型的语气表现仍待复验。

**独立审计修复（11月8日）。** OpenAI 兼容请求拒绝重定向。已启动的项目命令在超时或状态不明时保留待核对回执，已知退出码单独保留。拒绝同批待确认项和重开聊天都能保留未知回执。命令参数拦截已复现的直接内联执行和 Git 临时配置绕过。记忆开关由宿主持久化，前台、续轮和定时任务读取当前值。新版备份恢复保留任一侧的关闭选择，缺少开关的旧备份恢复后两项关闭。永久清空覆盖历史记忆表，删除替代项时旧记录保持暂停。明确缺少模型配置时，发送会打开设置并保留草稿和附件。隔离 Chromium 核对了保存后手动发送、弹窗焦点和工作台网页打开。整仓离线 10/10 通过。本轮界面验收使用隔离浏览器，原生 WebView2 与真实模型仍待复验。

### 3.3 模块如何联动

当前按用户要求继续陪伴／上下文专项，主线产品扩展与前台验收仍暂停。`companion_eval.py`、`agent_eval.py`、`context_eval.py` 默认离线，只有显式 `--live` 借用已保存ChatGPT/Luna；参考答案不进入模型，不自动切换付费API。完整实验方法、历次报告与失败边界统一保留在[评测与架构记录](research/companion-evaluation-minimal.md)，本路线图只维护当前结论，不重复逐轮日志。

已保留的生产修复：Main与 `recall_memories` 共用有界active／未替代global词法召回，移除旧散列向量与整句LIKE回退，错误不伪装空记忆；Context不重复投影constraint。ToolLayer只消除与原生schema重复的说明，公共安全规则不缩写。文本摘要不接受截断、空、非终态或非缩短输出；准备和执行共用一次绑定的provider／窗口／输出限额，本地profile先加载，不重读模型设置。沿用既有权限、事实、恢复、停止学习与记忆关闭边界，不新增认知模块。

当前模块的状态归属与可复用接口如下；不同层级不按文件大小强行合并：

| 模块 | 拥有的状态／对外职责 | 不应承担 |
| --- | --- | --- |
| React 工作面与 typed commands | 个人／项目选择、可见消息、进度和待确认展示；复用 IPC 数据合同 | 另存一套任务终态或自行批准权限 |
| 前端会话事件与工作投影 | `agent-event.ts` 按 Main session 共享一个可即时取消的原生订阅；`workspaceActivity` 按工作区＋Main 归属统一读取、合并在途刷新、活动期轮询和最后视图释放 | 由每个视图另建轮询、让迟到响应改写新空间、以事件文字生成任务状态或重试工作 |
| 自动化与活动的前端刷新 | `projection-refresh.ts` 在自动化列表、聊天事项回看及工作区活动内复用同一读序：同一读取范围最多一轮在途读取，期间的更新提示合并为一次补读；切空间或离开时丢弃旧读取的发布资格。聊天头部和工作台的事项回看按空间共享快照和订阅。列表只在有活动运行且可见时补轮询，操作状态按任务分开 | 把刷新提示当作执行结果、在前端重试未知操作、让另一张任务卡解除本卡的操作锁；不改变后端调度并发与权限 |

Main control 直接调用 `DelegationServiceHandle`，不经过定时器或额外循环包装。交付限制只在装配时绑定，Adapter 方法必须显式实现；后台轮询与前台操作继续由同一服务互斥串行。普通 Main 可按需调用 `list_delegated_work` 查看本会话最近 12 项未完成任务，再以精确的 delegation／attempt 对调用 `stop_delegated_work`；不在每轮上下文复制任务清单，自动交付总结不获得这两项工具。停止不回滚已完成操作，清理未完成时明确回报；未知落盘保留恢复资源，不把模型理解目标、原生点击或多委派恢复视作已验收。后续能力继续复用该接口与既有终态清理路径，不另建控制服务。

上下文按 [ADR-0004](architecture-decisions.md#adr-0004) 加深现有准备接口，而不引入脑式记忆框架：已保存全局约束每轮从持久存储独立投影，Main 与检查工具复用读取器；带来源 ID、完整规则和遗漏数量，排除过时／无法归属记录，受长期记忆开关控制，不受学习开关、当前用词或摘要替换影响。相关记忆不再重复注入约束或召回已被替代的条目。权限、恢复与交付仍在原控制面中；受控中断／并发、原生批准证据和未知结果的人工检查边界见下表，下一步转向普通应用的低风险日常任务，不以新增记忆机制代替真实任务能力。

MCP 按需连接采用已确认的“缓存目录＋调用时启动”，不做回合内动态扩充工具集。新服务先在设置中连接一次，成功发现的工具定义单独落库，不保存凭据、启动参数或原始注解；Main 装配固定目录不会启动进程。首次实际调用及批准继续复用原权限链，复核工作区、配置与实时 schema；定义变化不执行旧调用。命令／参数变化、停用、删除、凭据修改及恢复相应服务配置会使目录失效；目录不随备份导出或导入。停止只结束进程，保留后续任务按需连接的可能，禁止后续使用应停用服务或撤销工作区授权。连接后沿用现有应用级进程生命周期，不承诺任务结束立即退出或系统安全沙箱。

主对话状态条与右侧任务面板复用同一工作投影，不再各自轮询；空状态由 Main 事件唤醒，后台刷新保留已知内容，失败明确标为上次记录。仅可见且仍有后台活动时按原 3 秒间隔刷新；隐藏、等待用户决策、无工作或最后视图关闭时停止该轮询。原生订阅与消息流共享，Main 重连只释放自己的租约；Dev HTTP 继续使用原 Main 事件轮询回传只读刷新提示，不另建时钟。旧的无入口本地待办页／样式／独立存储已删除，`tasks` 导航仍指向现用自动化页，工作台与后端持久任务队列保留，不删除旧 localStorage 数据。历史动态、当前委派投影、Reviewer 与确定性 verifier 职责不同，不能按名称或文件大小直接合并。

主对话事项可携带 automation／workspace 身份定位自动化卡片；导航不切换归属、不执行、不重试，删除或归属变化明确提示，后台刷新不抢走焦点。自动化总页通过 `get_automation_dashboard` 一次读取定义和当前回执摘要，沿用既有 owner-unknown／running／queued 优先级和通知跳过规则；摘要正文截取 400 字并保留截断标记和通知说明，原始输出仅在展开单项运行记录时按需读取。记录读取失败或迟到不覆盖当前回执，脚本结束不等于业务完成；暂停未来计划与精确停止本次仍走原执行接口。原生 IPC、Dev HTTP 和类型封装同步，Main 的工作区限定 overview 不放宽，无新增调度器、缓存、依赖或数据库迁移。前端原历史排序路径及对应重复排序用例移除，规则留在后端验证；此处不宣称实际耗时或内存基准已改善。

构建、启动隔离应用、输入测试请求、观察结果、读取回执、排查失败及整理证据由开发者完成，不再把整套测试步骤交给用户。先跑通真实用户路径，复用有效测试，仅为实际缺陷补最小回归；测试数量和通过率不替代业务结果。
