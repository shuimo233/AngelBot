# AngelBot 当前统一路线图

> **状态：当前唯一的实施路线图（更新至 2026-10-26）。**
>
> 本文只维护当前能力、有效验收、缺口与唯一推进顺序；不追加逐轮开发日记。固定历史见 [验收记录归档](archive/implementation-evidence-2026-10-17.md)。

## 1. 产品目标与不可变边界

AngelBot 是本地优先、面向单一用户的 Windows 通用个人助手；长期陪伴与减轻应用／任务切换负担是核心，不以邮件、编程、长程研究或大型项目自治定义自身。

用户只与 Main 对话，日常是入口，项目承载持续工作；每个项目一个可见主对话，文件／浏览器／任务工作台按需展开。Main 负责上下文组织、派发与交付，访问仍按空间隔离；子代理没有用户入口、递归委派或主项目写权限。候选 worktree／sandbox 是临时隔离资源，不是正式项目或 OS 沙箱。

完整产品和授权边界见 [设计原则](design-philosophy.md)，术语见 [CONTEXT.md](../CONTEXT.md)。习惯学习首先改善相处体验，不以强制流程优化替代业务能力。

## 3. 当前实现与验收总览（2026-10-26）

**结论：已有可运行的个人助手底座，当前适合可控试用，尚不适合无监督地托付大部分日常事务。** 不按代码量、测试数或历史里程碑计算完成百分比。离日常主力工具的差距主要在任务覆盖、真实业务完成与失败恢复，不是只剩美化和打包。以下状态优先于后面的历史快照；后续只更新本节和对应验收记录，不再另建进度表。

本轮整理的代码围绕“日常任务与恢复可靠性”：Main／有界委派与独立审校、MCP 凭据隔离及按需连接、日常结果与备份恢复、受控脚本／MAA 运行回执、单窗口操作，以及主对话／工作台／设置的连续性。当前离线全量为 Python18、前端744、Rust1243，7项 opt-in 不计通过；受控原生与真实模型证据分别列在 3.4，不互相抵扣。合并开发里程碑不等于安装包发布、普通版已更新或通用无人值守任务已经验收。

仓库默认主分支于 2026-10-26 按用户要求从公开 `dev` 正式更名为 `main`；当前开发 PR 直接进入 `main`，以 squash 合并，不再设 `dev`→`main` 晋升。原公开历史未改写，原 `Integration PR gates` 的三个必需检查、禁止强推／删除和无绕过均保留并读回确认。历史归档中的 `dev` 仅表示当时状态，不是当前提交目标。

草稿 PR 已在打开、代码更新和重开时运行全部 Windows 检查；转为可审阅只复核元数据策略，不再对未变源码重跑 Windows 构建。`main` 推送、手动触发、两项 Windows 作业和三个必需检查均保留，不以去重替代验证。

从日常使用看，仍有四组必须补齐的门槛：**普通应用／网页的真实任务覆盖**（已有真实计算器闭环、有界项目资料和网页 DOM 任务，但不代表常用软件、跨应用及独立浏览器画面均已验收）；**长期连续使用**（长会话质量、断线／凭据续期和多日恢复）；**到点自动化与通知**（实际队列、投递可见性、停止与清理）；**干净安装／升级／恢复**（不能用调试构建代替）。小白最需要减少“能处理什么、完成了什么”的猜测；重度使用者最需要连续性和异常恢复证据。当前可以试用已验收的小任务，但不能据此承诺上述四组已完成，也没有可靠依据估计剩余天数。

### 3.1 如何判断“完成”

本轮提交审查已补齐两个异步导航问题：工作区打开／创建显式返回接纳结果，侧栏、自动化结果、快捷切换和项目路由同步核对；较新的页面意图以及重开的弹层不能被旧回调覆盖。快捷切换选择“当前空间”也走接纳流程，使此前未完成的旧打开失效。两轴风险重点审查发现的各一项 P2 均已修复并复核关闭；这不是对所有修改逐行穷尽的人工审查，也不替代远端必需检查或真实验收。

本轮验收校准了关闭通知、MCP 缓存目录、附件结果区权限及统一操作回执的旧预期，保留精确失败与持久回执检查。替换流式节点的等待回归先红后绿，九处同类等待每轮重新定位，仍要求相同正文可见及原20秒边界；缩窗验收须真正达到不超过 `1000×540`，再满足原可用性与30%附件高度限制，5秒未达标仍失败。增量需求复核发现的“任意缩小即可通过”缺口已关闭。临时诊断已移除；全部失败、先红后绿及全量证据保留在 `logs/pr-milestone-20261026-` 日志组，详细履历见 [PR #3](https://github.com/shuimo233/AngelBot/pull/3)，不再逐轮扩写进度文档。

单窗口图像的远端旅程仍真实返回 `SCAN_TIMEOUT`（`logs/pr-milestone-20261026-remote-native-identity-smoke.log`）。Win32 枚举重写未解除阻塞，已撤回，不维护第二套发现实现；临时诊断也已全部清理。当前最小修复统一八个 UIA 入口的系统 PowerShell／最小环境／MTA 构造，修正仅控件执行入口使用 MTA、截图与观察等入口仍默认 STA 的不一致。真实子进程回归先观察到 STA 而失败，再观察到 MTA 且仅一个参数而通过（`uia-apartment-red.log`、`uia-apartment-green.log`，同一日志组）；这只证明线程模型，不证明原生截图。窗口唯一性、密码扫描、身份复核、整次8秒／更短调用方预算、取消、回收及权限均不变。另修复恢复验收夹具把 Windows 长短路径当作不同目录的错误，保留历史完整性与禁止重放断言。最终全量及原生结论仍以 PR #3 最新固定提交的三个必需检查为准；未通过不得合并，合并也不等于发布或日常托管就绪。

- **已实现**：生产入口、调用方、存储和必要 UI 已接通；不代表真实任务成功。
- **离线验证**：确定性测试通过，证明被测契约；不能证明真实模型、第三方应用或系统通知。
- **原生夹具验证**：Windows 上实际执行过，但对象是自有窗口、临时数据库和脚本化模型；不能外推到任意应用。
- **真实日常验收**：实际配置的模型、应用和明确授权的小任务完成发现、授权、执行、核验、原对话交付及失败恢复，才可提升相应能力的使用承诺。

### 3.3 模块如何联动

```text
个人／项目 Main 对话
  → typed IPC → 现有 session 准入 → ForegroundTurnCoordinator
  → ForegroundRunStore 原子预留 + ContextAssembler 按空间组装
  → 统一 Agent 循环 + 当前空间工具面
      ├─ 日常动作：既有授权／精确确认 → 桌面、文件或 MCP adapter
      ├─ 委派：Supervisor outbox → bounded worker → 独立 Reviewer
      │         → Main 接收；候选另经用户确认 → Materializer
      └─ 自动化：既有定义／调度／回执 → 当前空间 Main 输入或确定性执行器
  → 独立结果核验／不确定性归类 → 持久终态 → 同一 Main 对话交付
```

上下文组装不负责进程执行，Supervisor 不执行工具，Reviewer 不生产原候选，verifier 只给技术证据，前端不决定是否扩权。自动化不是另一位用户可见 Agent；截图理解也不自行产生点击权限。专业 Codex／Claude Code 执行器尚未形成生产适配链，不能把当前 Responses 模型接入标记为该能力完成。

当前模块的状态归属与可复用接口如下；不同层级不按文件大小强行合并：

| 模块 | 拥有的状态／对外职责 | 不应承担 |
| --- | --- | --- |
| React 工作面与 typed commands | 个人／项目选择、可见消息、进度和待确认展示；复用 IPC 数据合同 | 另存一套任务终态或自行批准权限 |
| 前端会话事件与工作投影 | `agent-event.ts` 按 Main session 共享一个可即时取消的原生订阅；`workspaceActivity` 按工作区＋Main 归属统一读取、合并在途刷新、活动期轮询和最后视图释放 | 由每个视图另建轮询、让迟到响应改写新空间、以事件文字生成任务状态或重试工作 |
| session 准入、`ForegroundTurnCoordinator`／`ForegroundRunStore` | 可信会话身份、前台运行预留、确认续接与终态持久化 | 自己实现子代理调度或电脑操作 |
| `ContextAssembler` 与记忆／资料模块 | 按当前空间与预算组织上下文；投影已持久化事实 | 全量复制其他项目历史、以摘要替代执行授权 |
| `AgentRunner`／`ExecutionKernel` 与 `ForegroundToolSurface` | 单一工具执行循环、当前工具装配、执行时权限与确认 | 吞并领域状态机或把工具返回文字当成功证明 |
| Workspace Supervisor 与 `DelegationIssuance` | 工作区优先级、已授权工作、不可变工作包与派发回执 | 启动另一套执行循环、让模型决定路径／凭据／lease |
| `DelegationServiceHandle`／`DelegationService` | **唯一串行委派服务**：生命周期、交付接收、Main 查询／停止／决策／重试／落盘协调；装配时绑定同一份交付限制 | 把 Main 业务经定时器透传，或在调用端另建业务状态 |
| `DelegationPumpHostHandle` 与 Scheduler | Host 仅拥有定时器、先 poll 后 reconcile 及 Main 唤醒；Scheduler 拥有 outbox CAS、容量和租约恢复 | 默认空实现业务操作；重复持有可变策略或新增消息队列 |
| Worker／Reviewer／ChangePipeline 与平台 adapters | 有界生产、独立审校、确认后精确落盘；文件／Windows／MCP 各复用现有适配 | Reviewer 修改生产者候选，或把 worktree 当作系统安全沙箱 |
| 自动化、备份与恢复 | 既有调度／回执、持久数据与凭据恢复；需要 Agent 时走同一 Main 入口 | 旁路会话准入、恢复时盲目重放未知副作用 |

Main control 直接调用 `DelegationServiceHandle`，不经过定时器或额外循环包装。交付限制只在装配时绑定，Adapter 方法必须显式实现；后台轮询与前台操作继续由同一服务互斥串行。普通 Main 可按需调用 `list_delegated_work` 查看本会话最近 12 项未完成任务，再以精确的 delegation／attempt 对调用 `stop_delegated_work`；不在每轮上下文复制任务清单，自动交付总结不获得这两项工具。停止不回滚已完成操作，清理未完成时明确回报；未知落盘保留恢复资源，不把模型理解目标、原生点击或多委派恢复视作已验收。后续能力继续复用该接口与既有终态清理路径，不另建控制服务。

上下文按 [ADR-0004](architecture-decisions.md#adr-0004) 加深现有准备接口，而不引入脑式记忆框架：已保存全局约束每轮从持久存储独立投影，Main 与检查工具复用读取器；带来源 ID、完整规则和遗漏数量，排除过时／无法归属记录，受长期记忆开关控制，不受学习开关、当前用词或摘要替换影响。相关记忆不再重复注入约束或召回已被替代的条目。权限、恢复与交付仍在原控制面中；受控中断／并发、原生批准证据和未知结果的人工检查边界见下表，下一步转向普通应用的低风险日常任务，不以新增记忆机制代替真实任务能力。

MCP 按需连接采用已确认的“缓存目录＋调用时启动”，不做回合内动态扩充工具集。新服务先在设置中连接一次，成功发现的工具定义单独落库，不保存凭据、启动参数或原始注解；Main 装配固定目录不会启动进程。首次实际调用及批准继续复用原权限链，复核工作区、配置与实时 schema；定义变化不执行旧调用。命令／参数变化、停用、删除、凭据修改及恢复相应服务配置会使目录失效；目录不随备份导出或导入。停止只结束进程，保留后续任务按需连接的可能，禁止后续使用应停用服务或撤销工作区授权。连接后沿用现有应用级进程生命周期，不承诺任务结束立即退出或系统安全沙箱。

主对话状态条与右侧任务面板复用同一工作投影，不再各自轮询；空状态由 Main 事件唤醒，后台刷新保留已知内容，失败明确标为上次记录。仅可见且仍有后台活动时按原 3 秒间隔刷新；隐藏、等待用户决策、无工作或最后视图关闭时停止该轮询。原生订阅与消息流共享，Main 重连只释放自己的租约；Dev HTTP 继续使用原 Main 事件轮询回传只读刷新提示，不另建时钟。旧的无入口本地待办页／样式／独立存储已删除，`tasks` 导航仍指向现用自动化页，工作台与后端持久任务队列保留，不删除旧 localStorage 数据。历史动态、当前委派投影、Reviewer 与确定性 verifier 职责不同，不能按名称或文件大小直接合并。

主对话事项可携带 automation／workspace 身份定位自动化卡片；导航不切换归属、不执行、不重试，删除或归属变化明确提示，后台刷新不抢走焦点。自动化总页通过 `get_automation_dashboard` 一次读取定义和当前回执摘要，沿用既有 owner-unknown／running／queued 优先级和通知跳过规则；摘要正文截取 400 字并保留截断标记和通知说明，原始输出仅在展开单项运行记录时按需读取。记录读取失败或迟到不覆盖当前回执，脚本结束不等于业务完成；暂停未来计划与精确停止本次仍走原执行接口。原生 IPC、Dev HTTP 和类型封装同步，Main 的工作区限定 overview 不放宽，无新增调度器、缓存、依赖或数据库迁移。前端原历史排序路径及对应重复排序用例移除，规则留在后端验证；此处不宣称实际耗时或内存基准已改善。
