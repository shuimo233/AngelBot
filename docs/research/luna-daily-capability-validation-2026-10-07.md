# Luna 日常能力验收与专项适配

日期：2026-10-07（Asia/Shanghai）。本轮使用用户已连接的 ChatGPT 套餐与 `gpt-5.6-luna`，检查普通对话、本地提醒、Main Agent 自动化和桌面能力发现；不更换模型、不自动切换付费 API，也不以离线测试替代真实使用。

## 当前结论

AngelBot 已能通过 Luna 调用本地工具并返回普通查询结果，创建的一次性提醒也确实产生了本地触发回执。只读 Agent 自动化重测已完成，但此前的凭据获取故障仍未定位，通用 computer use 也不具备完整视觉与网页操作链。当前是有边界的 Windows 试用工具，不是可全面接管电脑的日常主力助手。

本轮优先修复会造成误执行、重复副作用或误导用户的接缝，复用现有 Supervisor、运行恢复、工具暂停和回看模块；没有新增调度器、权限档位或第二个用户对话入口。

## 本轮修复

### 自动化语义与事务一致性

前后端仅接受当前真正实现的每日时刻：`H:MM` / `HH:MM` 或“每天”加时刻；时、分严格校验。前端不再提供尚未实现的工作日、每周或明天选项。一次性提醒继续由 Main Agent 的既有提醒工具处理，不新增前端写入旁路。自然语言解析必须出现明确每日频率；编辑输入会使旧解析草稿失效。

旧的不支持频率保留定义与历史，但停用并标为需处理，清空下一次时间；准备及最终准入均拒绝旧排队项，已越过启动边界的运行身份保留，不自动重放。

暂停的 Agent 定义不再提供可点击的“立即执行”，而是禁用并提示“先启用再执行”；保留现有“启用”入口，脚本与通知的手动执行行为不变。公开组件回归覆盖暂停拒绝、启用后执行和两类兼容行为。

Agent 输入、自动化运行回执与下一次调度推进共用一个事务，复用 `WorkspaceSupervisor::submit_in_tx`。任一步写入失败，三者一起回滚，避免出现无回执输入或失败后重复入队。回归覆盖事务故障、旧频率、准入前变化和已启动身份保持。

### MCP 未知结果

transport 区分已知拒绝与请求接收后的未知结果：工具调用超时、断连、不可信响应或缺失结果不能作为普通参数错误提示模型重试。已派发但无可靠回执的调用复用 `RESULT_UNKNOWN`、`terminate_batch` 和既有暂停机制；未启动拒绝仍是普通错误。

没有新增 MCP 信任策略，也不宣称远端 exactly-once。原有整体执行权限和服务范围保持不变，迟到结果不成为自动重复动作的依据。

### 主对话回看

回看实际包含通知、Agent 和脚本，原“提醒回看／待提醒”容易与仅查询一次性通知的 `list_reminders` 冲突。现改为“事项回看／待执行”，数据选择、空间隔离和工具权限范围不变。“今日触发”不是任务成功或系统通知送达。

### 失败投影与凭据诊断边界

主对话的中断恢复原先把已持久化 `LlmError` 覆盖成无原因的通用未完成提示。最小修正仍在同一 provisional → `needs_attention` 事务内，仅按同 run/session 的事件类型与错误 code 投影固定安全提示；无已知分类保持旧兜底，不读取或拼接底层错误正文，不转发缓存成功终态，也不改变已启动任务的重放边界。

只读源码核对确认自动化与普通对话使用同一个模型工厂、`PlanCredentialSource`、进程锁、跨进程锁和受保护存储；没有发现可证实的自动化专属凭据旁路。当前 provider 将锁、存储、授权校验、刷新请求／响应及保存错误统合成一个安全文案，导致现场原因无法进一步区分。下一步应在这一接缝增加固定安全阶段分类，而不是输出 token、授权引用、远端响应或假定需要重新登录。创建后的连接失败与后续凭据获取失败可能相关，但本轮证据不证明二者同源。

## Codex 的参考边界

核对官方 `openai/codex` 固定提交 `5a3140176e668a2f72f3c098490eb7f7052d9d85`，借鉴工具执行契约、typed content、终态幂等与取消收尾，不迁移整个编码 harness。仓库为 Apache-2.0；本轮未复制其源码。公开 CLI、SDK、app-server 并不意味着完整 Codex 桌面 Windows computer-use helper 可移植。[源码与许可](https://github.com/openai/codex/tree/5a3140176e668a2f72f3c098490eb7f7052d9d85)、[官方公开组件](https://learn.chatgpt.com/docs/open-source)

Luna 的模型能力不能替代 AngelBot 的传输与执行链。套餐入口允许符合约束的本地工具与图像输入，但不支持托管 native computer use、hosted MCP 等能力；因此适配方向是 Luna 判断、AngelBot 本地受控执行，不悄悄切换计费路径。[套餐入口限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

逐模块源码、测试接缝与来源见 [Codex 日常能力适配参考](codex-daily-capability-reference-2026-10-07.md)；这份参考是源码调研，不是实机通过证明。

## 接下来优先做什么

1. 查清 ChatGPT 凭据读取／刷新阶段的偶发失败，扩展普通桌面版下的 Agent 自动化故障恢复旅程；保持开始后不自动重放的边界。不能因之后普通查询和一次重测成功将原故障标为已修复。
2. 工具结果 → 通用消息 → Responses 的静态 PNG 基础链和 WGC 单窗口工具路径已在后续阶段补齐，分别见 [工具图像链路验收](tool-image-bridge-2026-10-07.md)、[单窗口观察记录](single-window-observation-2026-10-07.md)。旧观察范围不静默扩大，图像瞬时且不授予动作权限；离线测试通过不等于窗口或模型通过。接下来先验收非私人原生捕获夹具，再验证用户明确授权窗口的真实 Luna 图像输入和完整结果，不另建视觉 Agent 或权限框架。
3. 深化原有 UIA 观察、窗口选择和浏览器正文语义。当前命名控件、有限快照和短时引用不能覆盖任意网页或不可读控件；不得以未授权坐标点击作为静默兜底。截图理解不等于执行授权。
4. 在用户明确选定的应用范围内验证真实“观察 → 预检／确认 → 动作 → 回读 → 结果回流”任务；继续复用 Supervisor、工作区主对话和现有恢复状态，不把工具派发当作业务完成。

正式日常主力使用仍需真实应用多步结果、网络和凭据故障恢复、系统通知送达及安装／更新质量门。离线全量绿色与某条模型查询成功，均不能替代这些验收。
