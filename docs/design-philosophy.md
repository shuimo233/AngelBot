# AngelBot 设计原则与产品边界

> 当前产品约束；实现进度只在 [统一路线图](current-roadmap.md) 维护。
> 本文合并原设计哲学和日常助手决策票据，取代早期“每次副作用都逐次批准”“只有一个执行者”“只保留四个工具”等过时设定。

## 1. 为一个人减轻负担

AngelBot 是开源、本地优先的 Windows 个人助手，不需要 AngelBot 云账户。核心价值是减少用户在应用、资料、会话和执行工具之间切换、重复解释与跟进事务的负担，而不是展示 Agent 框架本身。

长期陪伴是核心目标：交流连贯、主动记住轻微日常习惯、让人用起来舒服。它不冒充真人，不替用户做情感决定，不利用陪伴关系诱导授权，也不把自己塑造成用户唯一的情感出口。

文件、应用、浏览器、自动化、连接服务和轻中量项目工作是同一个助手的能力；邮件、日历和编程都不是单独的产品身份。不以长程研究、超大型项目自治、多用户协作或云控制面为目标。

## 2. 一个 Main，日常与项目连续

- 用户始终面对同一位 Main Agent。日常是主要入口，项目承载持续工作的资料和上下文，每个项目只投影一个主对话。
- 个人空间可以知道有哪些项目在推进，但不因此获得项目文件内容或访问权限；具体工作进入对应项目。
- 日常任务不为交付文件而强迫建项目：应用数据库旁的自有结果区复用既有文件工具、`angelbot-file:`、只读预览、原生另存和备份，不另造结果文件工具或存储流水线。文件默认保留；这个文件根目录不授予项目命令、委派或其它用户目录权限。网页下载须由已启用且受信任的工具明确写入此目录，不从工具输出任意路径自动导入；MCP 不是系统沙箱。恢复不覆盖已有不同内容的结果，旧备份不会删除结果。
- 文件、浏览器和任务工作台保留，按需展开；用户以助手和结果为主，不必学习子代理控制台。
- 一个 Main 不等于只能有一个执行者。有界 Explorer／Implementer 可并发工作，写入冲突与外部副作用仍须串行或明确仲裁。
- 子代理仅由 Main 派发，不递归委派、不直接与用户对话。候选在有生命周期的 worktree／sandbox 中形成，独立 Reviewer 审校后再由 Main 交付；确定性 verifier 只提供技术证据。
- 用户知道子代理在做什么及其真实状态，不展示不可估算的完成百分比、隐藏推理或要求用户审阅原始工具流水。
- 专业编码执行器可以是可选能力，不为此自建重型编码 harness；尚未接入的执行器不得写成现有能力。

## 3. 用户主权与少打扰的授权

能力是否接入、工作区／应用范围、当前执行权限是不同的门。模型、网页、工具输出或子代理都不能自行扩权。

| 操作 | 授权原则 |
| --- | --- |
| 授权范围内的只读观察 | 可自动执行，不因“只读”越过工作区、应用或来源边界 |
| 外部查询 | 先有已启用能力及可信端点；ask 下按语义确认，不能伪装成本地观察 |
| 有界项目修改 | ask 确认具体动作；workspace_auto 只覆盖已准入的工作区能力，不等于通用电脑权限 |
| 外部动作 | 遵循可见的整体权限；full_access 是对已准入能力的持续授权，不重复增加一套独立确认模式 |
| 受保护动作 | 已知的凭据／安全策略变更、购买、不可逆删除或提权等仍须专项确认，缺少安全语义接口时不支持 |

- 保留可信应用范围列表；整体权限不能替用户新增应用、连接服务或扩大子代理 lease。
- 用户选择完全启用第三方 MCP，表示信任该服务。风险标签未知时不能承诺识别其所有危险操作；不能一边接受这项信任，一边又假定每个工具都会被独立风险拦截。
- 完全访问沿用任务授权，不因累计 8 次副作用工具调用再次暂停；总时限、无进展、停止、范围及已有风险确认、结果未知不重试仍然有效。ask／工作区自动维持原次数暂停。次数预算不是风险识别，也不向子代理新增权限。
- 已有桌面文本填写／控件操作的精确确认不因 full_access 消失；图像观察授权也不自动授予点击或发送权限。
- 确认说明动作、目标、所属空间／账户与可逆性；秘密必须隐藏，仅在核对动作确有必要时显示相关内容。批准绑定持久调用身份和参数，单次消费；参数变化重新确认，拒绝持久终止。
- 结果区分已核验、仅已派发、拒绝、不可用、失败与未知。超时／崩溃后的未知副作用不能自动重放，也不能用“已发送调用”冒充业务完成。
- 可恢复性依赖最小持久状态和证据，不要求用户阅读每次工具调用的审计面板。对话回溯不等于撤销已经发生的外部动作。

## 4. 记忆首先服务于相处

- 会话历史、项目事实、任务证据和个人习惯分工，不把所有旧消息永久塞进上下文；近期完整轮次与结构化 checkpoint 保持目标、约束、决策、操作、证据和待办。
- 项目本身是事实来源，必要时重新读文件；摘要和旧分支状态不能代替当前项目核验。
- 轻微偏好可以在启用学习时形成有证据的候选或暂定记忆，但不能把一次表达当成长期事实。用户应能查看、纠正、忽略、忘记或停用。
- 显式要求、当前消息和用户人格设定优先于推测偏好；不自改 persona、不利用学习改变权限或自行激活新工具。
- 流程经验与技能提案是可选增强，不是陪伴能力的主要目标，也不强迫用户把普通谈话变成审批任务。
- 学习与长期记忆开关约束执行和恢复，不只改变 UI。自然多日效果必须另行验收，不能用一次提取成功作证明。

## 5. 界面与提示词像日常工具

- 先给结果与可行动的下一步；具备已授权能力时完成真实动作，不用说明文字假装保存、发送或执行。
- 系统提示词由短而稳定的核心规则、当前实际工具和有界上下文组成，不为每个具体请求增加特判。
- 安全且不改变用户重要选择的细节采用合理默认值；涉及目标、范围、费用或不可逆后果时才询问。
- 首次启动不被模型配置阻断。配置和问题引导放在设置或需要能力时的对话提示中，不把使用困难归咎于用户。
- 日常和项目共用稳定的字体、对齐、间距、状态语言和过渡；设置导航左对齐，减少大圆角、独立卡片堆叠和装饰性渐变。
- 不用 emoji、魔法符号或拟人化功能装饰传达状态。可借鉴《明日方舟》的任务层级与栅格原则，不复刻资产；亮黄／橙等强调色也须克制、可读、双主题一致。
- 语言可跟随系统；键盘、聚焦、加载、失败、空状态、深色和减少动态效果与正常界面一起验收。可访问性／本地化的正式支持承诺不能由几个界面元素推断。

## 6. 平台、模型与连接服务

首发环境面向 Windows 11 x64 交互式用户会话。平台相关行为收在凭据、驻留、通知、文件授权、外部认证、浏览器／桌面操作、安装／更新／恢复这些接缝中，不再平行建设一套控制面。

- **能力选择：** 优先现有文件／应用语义能力，再固定 URI／固定命令 adapter、工作区已启用 MCP、浏览器语义及有界 UIA。复用前台工具装配入口，不另建只转发同样规则的路由器。
- **操作边界：** 不暴露任意 shell、PowerShell、可执行参数、坐标键鼠、UAC 或自动提权作为通用兜底；不接管用户默认浏览器配置。具体 Windows 接口与限制见 [平台能力依据](research/windows-daily-use-capabilities.md) 和 [computer use 依据](research/windows-generic-computer-use-2026.md)。
- **后台行为：** 开机驻留是用户选择，不预先启动每个辅助程序；明确未运行、休眠、关机和未登录的限制，不承诺超出当前调度能力的执行。
- **模型接入：** 支持兼容协议和用户配置的端点，核心业务不依赖固定厂商、模型名或私有响应形状。能力、成本与失败不能靠静默换供应商解决；套餐接入不等于专业编码执行器。
- **连接策略：** 稳定能力接口之下优先供应商原生 delegated API，IMAP／SMTP／CalDAV 是兼容 adapter，不是另一套权限模型。系统浏览器 PKCE、受保护本地凭据、分阶段 scope 和失效后重连沿既有边界；首批可用轮询／delta，不要求 AngelBot hosted webhook。具体提供方合规与接入条件见 [连接服务依据](research/connected-services-windows.md)，没有真实闭环不宣称支持。
- **发布目标：** 签名的按用户安装、更新与可恢复本地状态属于验收目标，不是当前已完成证明；不以机器级服务、提权或后台无界驻留换取覆盖率。

## 7. 保持工程克制

优先复用既有会话循环、上下文、Supervisor、隔离、权限、自动化和验证模块。只有具体任务暴露出无法表达的边界时才增加接口，不因借鉴 Pi、Codex 或其他项目复制一整套框架。

稳定架构原因在 [架构决策](architecture-decisions.md)，委派与网络的精确合同分别在 [委派规范](delegated-agent-framework-spec.md) 和 [网络规范](delegated-network-capability-spec.md)。这些是设计约束，不是实现清单；当前状态和下一步只在路线图维护，真实发布条件只在 [桌面验收清单](desktop-beta-checklist.md) 签收。
